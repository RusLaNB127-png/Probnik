# Проверка страниц репозитория

Все приложения здесь — статические HTML-страницы без сборки. Проверяются
запуском в headless Chromium через Playwright.

## Запуск

- Chromium: `executablePath: '/opt/pw-browsers/chromium-1194/chrome-linux/chrome'`
  (путь `/opt/pw-browsers/chromium/chrome` не существует — смотрите
  версионированную папку `chromium-*/chrome-linux/chrome`).
- Страницы открываются по `file://` URL, сервер не нужен.
- Внешние CDN (unpkg и т.п.) в этой среде блокируются прокси (403) —
  подменяйте внешние библиотеки заглушками через `page.evaluate` после загрузки.

## PIXEL ARCADE (`arcade/index.html`) — основная платформа

Единый HTML-файл: платформа с регистрацией/входом (аккаунты в localStorage
`arcade-accounts`, сессия `arcade-session`, пароль хешируется чистым JS
SHA-256 — работает и по file://), хабом-каталогом игр, лидербордом из
аккаунтов и морским боем как одной из игр. Верхние экраны — `.view`
(`showView`), внутри игры — `.screen` (`showScreen`). `battleship/index.html`
теперь просто редирект сюда.

E2e: аккаунты в localStorage → для разных игроков нужны РАЗНЫЕ browser
context'ы (лидерборды у них тоже разные — это by design). Для проверки
мультиигрокового лидерборда на одном устройстве проще внедрить второй
аккаунт прямо в localStorage. Ключевые id: `#auth-nick`/`#auth-pass`/
`#auth-pass2`/`#auth-submit`/`#auth-toggle`, `#hub-lb`/`#hub-logout`,
карточки `.game-card`, `#lb-list .lb-row`. SHA-256 сверяется с Node
`crypto` (см. sha.js в скретчпаде) — при правках хеша прогнать сверку.

## Морской бой (внутри arcade, ранее `battleship/index.html`)

Мультиплеер через MQTT-over-WebSocket (публичный брокер, транспорт —
pub/sub по теме из кода комнаты). Для e2e без сети: открыть две страницы,
подменить `window.mqtt` фейком с общим «брокером» и связать их через
`exposeFunction`-реле, которое рассылает публикации обеим страницам
(готовый скрипт-образец в скретчпаде: полная партия двух игроков, реванш,
пробы). Реальное подключение к брокеру в этой среде не проверить — прокси
блокирует внешние WSS. Транспорт подключается сразу ко ВСЕМ брокерам из
`BROKERS`, поэтому фейк `window.mqtt.connect` вызывается несколько раз на
страницу — держите массив клиентов и рассылайте публикации всем; у сообщений
есть `id` для дедупликации. Ключевые точки: `genBoard()` доступна глобально;
рукопожатие — сообщения `kind:'join'`/`'welcome'`; ход определяется по
классу `#status` (`my-turn`/`enemy-turn`); конец игры — класс `active`
у `#overlay`.

Есть локальный режим «за одним ПК» (`mode==='local'`, состояние в `L`):
не требует сети, проверяется на одной вкладке. Кнопка `#btn-local` →
экран имён `#screen-local-names` (`#ln1`/`#ln2`, `#btn-local-start`) →
игра. Экран передачи `#pass-screen` + `#btn-pass-ready`, победитель —
`localOver`.

Профили и лидерборд в localStorage (`mboy-profile`, `mboy-leaderboard`).
ВАЖНО для e2e: обе страницы по file:// делят один localStorage — для
разных профилей хост и гость должны жить в РАЗНЫХ browser context'ах
(реле через exposeFunction работает и между контекстами). Вход в профиль:
`#prof-input` + кнопка в `#profile-box`. Результаты партий пишутся в
лидерборд автоматически (`recordResult`).

Ручная расстановка: редактор `E` (`initEditor`/`editorRender`), кнопки
`#btn-clear`/`#btn-rotate`/`#btn-reroll`, палитра `#ship-palette`,
клики по `#my-grid`. Кнопка выхода из игры — `#btn-exit` (онлайн шлёт
`{type:'leave'}` сопернику).
